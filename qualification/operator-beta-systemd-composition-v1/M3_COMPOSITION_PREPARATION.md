# M3 companion composition preparation

Source candidate only. No compiled, installed, admitted, or VM result is asserted.
Storage is below the owner reserve; preparation does not launch Cargo or guests.

The separate `m3_composition_driver.rs` uses the same qualification-only
Scenario/AG engine → signed issuance → Docket custody → ag-effectd systemd plan
→ Docket settlement → AG replay path as `composition_driver.rs`. The ordinary
composition executable retains its original fixed resolver and logical clock.
No new persistence owner, workflow engine, scheduler, or retry mechanism appears.

Cleanup alone requires the application-owned native receipt resolver copied
from the exact enrolled Labelwatch source. Its exact request, receipt identity,
cleanup step digest, AG subject and scope enter the observation binding.
Every AG resolution replays the real NQ receipt. The native final-witness expiry
caps AG standing, is checked before dispatch, and caps Docket execution-standing
against the exact issuance. An issuance has no new invented expiry field; its
observation/standing references remain authoritative. A fresh fixture60s answer
must not renew a native30s applicability interval. Tests of these joins and the
new stronger cleanup-v2 contract remain prerequisites, not presumed passes.

Other enrolled fixture steps use the explicitly developmental clean predicate
to qualify execution plumbing only. Their helper preconditions and output
remain separately checked; that predicate is not sufficient for final cleanup
and not production authorization. The fixture standing issuer is a root-enrolled
test premise, not a general operator-rights service.

`prepare_m3_build.py` checks exact clean AG/NQ/Docket/Labelwatch commits, archives
them into an absent output directory, and prepares a standalone Cargo crate.
It deliberately stops before lock resolution, vendoring or compilation. The
integration owner must pin that graph and build two clean offline Bookworm
copies, retain producer/image/source/toolchain hashes and compare package bytes.
The helper/runtime units must use that actual guest-compatible NQ binary, not
assume the host debug binary is compatible.

`m3_guest_setup.py` consumes root-enrolled source and the exact universal
websockets wheel. It initializes a disposable held SQLite fixture and separate
64MiB tmpfs backup filesystem and installs, but does not start, fixed main and
discovery units with Restart=no. Main acquisition intervals are disabled;
discovery points only to refused loopback with backstop disabled. Tmpfs does
not establish power-loss backup durability. Root writer accounts are a fixture
scope, not restricted production account qualification.

The forthcoming finite case runner must retain a distinct operation directory,
step input, unit fragment and AG/Docket evidence for each admitted interruption
cut. Positive execution uses the uninstrumented helper. Qualification-only
abrupt-exit wrappers count only if their exact cut was reached; failed wrapper
setup is not interruption evidence. Cases include before STARTED, STARTED,
effect-before-terminal, terminal, failed systemd start and no automatic retry,
plus application-specific rename/cleanup/release cuts from Labelwatch's matrix.
No terminal or incomplete operation is reset to obtain a cleaner result.

Remaining owner boundaries: Labelwatch owns generator/cut wrappers/observation;
NQ-ng owns factual cleanup replay; this Docket lane owns fixed driver, guest
composition and evidence reopening; root owns integration, package pins, VM
ports/disk authorization and independent final acceptance. M4's historical VM002
is not reused or restarted. A new combined candidate needs its own checker.
