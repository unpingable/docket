# M4 cold-cohort cut: bounded operator procedure

Candidate procedure, not yet qualified as a package/service transition. The
local stopped-copy witness is `day_two_cold_cut.py`; it establishes no human
operator trial or current authorization from historical records.

The original M2 and retirement binaries both identify as 0.1.0, but their
compiled factual profiles differ. The new binary refuses the original store's
profile semantic identity. Do not force that store open, overwrite its profile
identity, or call equal version strings compatibility evidence.

1. Quiesce collection and consequential execution using their existing owners.
   Verify stopped services and no in-flight operation. Uncertain execution must
   be reconciled by its owner before a cut; a database copy cannot resolve it.
2. With the exact old binary, create an absent-destination cold archive. Verify
   it using its preserved executable. Retain old package, configuration,
   admissions, owner execution records and enrollment identities separately.
   NQ archive verification does not establish AG/Docket authority continuity.
3. Retain the old store/configuration read-only. Install the admitted new binary
   cohort while services remain stopped. Use a distinct store and admissions
   directory; initialize with the verified archive's `manifest_sha256` as the
   `--legacy-manifest-digest`. This is a historical reference, not an import.
4. Inspect the new empty cohort. Perform fresh watcher test/admission and fresh
   applicable authorization enrollment through their existing owners before
   activation. Do not copy historical locks into active directories. Until these
   prerequisites pass, remain stopped and present the new cohort as unqualified.
5. Before activation or any post-cut records, rollback may reinstall the exact
   old cohort and restore its archive into an absent destination, after verifying
   no new execution/admission/write occurred. Verify old semantics with the old
   binary, and separately re-establish applicable current authority. Restore is
   not itself permission to restart or perform an effect.
6. After post-cut records, do not overwrite either history or blindly restore the
   old store. Stop affected services and use forward recovery under the current
   cohort. Preserve both histories and reconcile pending execution with Docket;
   history reconciliation or reverse semantic migration is not supplied here.

At any failure: retain command exits/stdout/stderr and both cohorts, leave
affected services stopped, and inspect the exact completed step. An interrupted
controller must first reconstruct package identity, configured store, service
readiness and owner execution disposition. Do not automatically repeat a cut,
restore, admission or effect. Missing post-cut evidence is not evidence that
nothing occurred. If that boundary cannot be established, use forward recovery.

Observed local fixture evidence: cold-cut-002 reopened the exact old archive,
initialized a fresh current store with its manifest reference, restored the old
store using its own binary with full typed-row equality, and imported a real
current artifact into new custody. The import changes the new store and triggers
the procedure's forward-only condition; it confers no diagnostic reliance.
The fixture does not execute a rollback after post-cut writes and does not
pretend an unexecuted action is a controller refusal.

Remaining qualification: real old-to-new package installation on a local VM,
fresh admissions and readiness, explicit pre-activation rollback case, and
interruption evidence. New-cohort runtime evidence from M4 VM002 can support
unchanged readiness/restore mechanics, not transfer qualification to this cut.
